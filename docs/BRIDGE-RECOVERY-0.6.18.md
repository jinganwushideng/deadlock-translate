## 可复现的旧代码风险与恢复缺口

最关键的额外风险：旧窗口脚本使用 host=context 兜底，找不到 DltSettingsWindowHost 祖先时仍可隐藏/删除当前原生面板。如果脚本执行上下文指向聊天面板，关闭翻译设置就可能删除聊天及其通信面板。模拟祖先/聊天上下文已复现旧代码删除错误目标；现场旧日志没有记录被删除面板身份，因此仍不能认定用户这次一定触发了该分支。

新菜单为自建宿主写入明确所有权标记，并记录同一 UI 根内的宿主引用。设置脚本只操作该宿主；定位失败或跨根时不修改、隐藏、删除原生上下文。不再靠当前面板兜底。

1. DltBridge 缺失后只查找，不重建；一个仍有效但已脱离聊天树的旧 HTML 面板也会一直被保留。两种情况都可能让游戏停止上报，后台却继续正常运行。
2. 标题事件永久优先，旧事件可能遮住新属性响应；非空旧属性还会遮住 GetTitle。并且未匹配当前请求的旧 JSON 也能把 initialized 设回 true，让重新加载逻辑被绕开。
3. 轮询回调链一旦丢失没有恢复入口。将这一点作为故障注入可以复现永久断连；这不是已经证明的游戏原生引擎行为。
4. 原生引擎把同一聊天面板移到另一棵 UI 根树时，原 ROOT 仍然有效，旧所有权检查不会迁移，可能保留旧界面引用。

## 本次修复

- 每次通信前检查自有 HTML 面板有效性和父子关系；仅重建自己的隐藏 HTML 叶节点，创建失败至少间隔 5 秒，不重载整棵聊天布局、不删除/导航原生失效面板。
- 逐一检查标题事件、属性、GetTitle 和属性回退；事件读后消费，重复内容缓存。只有当前请求/会话的有效响应能确认已连接。回退读取只在握手/等待响应时使用，避免平时无意义读取。
- 游戏内自有恢复控制器保留消息 ID、译文与发送确认，只重置通信状态；恢复调度时递增世代，旧回调即使晚到也不能形成重复循环。重试冷却不阻挡真正失去轮询后的恢复。
- 打开翻译设置尝试恢复；设置页原有轮询检查聊天循环是否停止。关闭窗口后只增加一次 3.5 秒延迟检查，健康时不重载，不增加常驻进程/线程，也不新建每帧全界面扫描。
- 聊天面板被引擎换到另一 UI 根时释放旧所有权并重新初始化；这类场景按新会话处理，不补发旧局发送任务。
- 游戏内异常提示明确区分“后台正常、游戏聊天连接中断”，提供“恢复游戏连接”。普通浏览器不提供无法执行的原生操作；旧 VPK 无恢复控制器时提示成套更新后重开游戏，不假报恢复成功。
- 新增 bridge-bound / bridge-rebuilt / bridge-reconnect / adapter-loop-resumed / adapter-root-moved 固定事件，不记录标题正文、URL、凭据或聊天内容，用于下次复现时确认是哪一类恢复发生。
