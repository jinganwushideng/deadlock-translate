## 诊断与性能边界

新增匿名任务事件 `hud-bound`、`hud-written`、`hud-expired`、`hud-host-repaired`、`hud-hidden-repaired`，与后台翻译事件使用同一会话内哈希关联；不记录正文、玩家名或原始消息 ID。新增固定数字 `hudBindings`、`hudExpiredResults`、`hudDeferredScans` 与 `gameLogDrops`，沿用轮转日志与一键导出。游戏事件仍受 64 条队列与批量传输上限保护，拥塞丢弃会累计 gameLogDrops，不能把截断日志里缺少事件直接当成未执行。written 仍只表示成功写入标签，不等价于 GPU 最终像素可见。

默认 200ms 增量扫描，单次发现上限 64 条边，已知父节点各最多 16 个子节点；最多 8 个 HUD 候选。常见两个有效根每次最多检查 48 个 HUD 行，历史只在打开聊天时补扫。单回调最多渲染两个任务，消息/结果 ID 与内存缓存保留原有上限。工作量比旧版略有增加，但有固定预算；合成树访问计数不是实际 FPS 或毫秒保证。标签恢复不新增云端请求，之前真正漏识别的消息会正常提交。

已退休会话保护缓存最近 64 个会话；不承诺识别一个从未到达过后台、或超过该窗口的任意旧会话。界面发现深度上限 24，不能宣称兼容任意整合包的无限层级。网络慢于原生气泡寿命时，仍只保留聊天记录译文，不延长或重弹原生气泡。
