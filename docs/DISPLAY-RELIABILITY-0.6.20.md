# 0.6.20 接收译文显示与并发

本轮处理“翻译已经完成，但顶部气泡偶尔没有译文”，同时保留真正过期的原生气泡不重弹的规则。版本 0.6.20 的后台、设置页、VPK、源码和完整安装器成套交付。

## 原生气泡模式

默认仍跟随原生气泡。隐藏、容器暂时缺失、原文字控件重建、节点暂时分离进入有限等待；明确的原生 Expired、面板销毁和消息内容改变分别终止旧视图。相同 ID 的旧内容子树仍在时，从当前未隐藏的原文字控件寻找其 MessageContents 祖先，避免继续写进旧宿主。不修改原生父面板可见性、淡出或输入状态。

等待只重试显示已有结果，不重新调用云端服务。队列最多 64 项，每个扫描周期最多处理 4 项，每次等待至少 400 毫秒，单轮最长 30 秒。原文字控件短暂缺失时不把它当成新空消息。原生容器重新显示也不再被重复统计成物理重建。

这不能验证最终屏幕像素。祖先样式、游戏裁切、其他 HUD Mod 和原生生命周期仍可能影响可见性；日志 hud-written 只表示标签赋值。

## 独立游戏内译文区

设置 → 显示与性能 → 接收译文显示方式 → 独立游戏内译文区。位于画面左侧，使用自建 Panorama 控件，不是外部悬浮窗，没有鼠标命中或焦点处理。默认 8 秒、最多 3 条，可设置 3～15 秒、1～5 条。

独立区展示已经识别、绑定的当前 HUD 聊天任务；聊天记录仍保留译文，独立区不再往原生气泡追加同一条译文。原生气泡消失后返回的翻译可以显示，计时从结果首次显示开始。快译被精翻原位更新但不延长时长，已经结束或被新消息替换的条目不因迟到精翻再次弹出。高频超过容量时替换最早显示的一条，记录替换计数；历史聊天不因此丢失。

只创建并复用最多 5 个槽位，控件被删除后恢复剩余显示时长，不重置计时。切局清空独立区，仍挂着的旧 HUD 行不重播。单独打开聊天记录不会把老消息播到独立区。此模式不补造未被识别的消息，也不能解决云端错误、后台未连接或整个游戏 UI 不可用。

## 两条消息即可并发

同局未完成的逻辑消息达到 2 条，即允许快译、精翻分别使用所配置的并发上限；首条仍立即开始，不等待凑批。混合模式两个阶段只算一条消息。降到 1 条时只限制后续准入，不取消已开始的请求。上下文专用、暂停、重复提交不增加计数，切局清零，旧响应不能污染新局。

服务总上限、发送预留、限流、超时、缓存和结果版本规则不变。模型思考开关、预算和用户选择的翻译模式不被修改。

## 诊断

新增固定事件 hud-wait、hud-restored、hud-retired、hud-retry-ended，以及 feed-mounted、feed-unavailable、feed-written、feed-ended、feed-displaced、display-mode。原因区分 DisplayHidden、DisplayContainerMissing、DisplayHostMissing、DisplayDetached、DisplayPanelGone、DisplayNativeExpired、DisplayMessageChanged、DisplayRetryExpired。

新增固定数值 hudWaits、hudRetryRecovered、hudNativeExpired、hudPanelGone、hudRetryDropped、feedRendered、feedExpired、feedDropped。事件按状态变化记录，仍受批量队列和丢弃计数约束，不记录聊天正文、玩家名、控件树、原始任务 ID 或设置凭据。导出摘要只含模式、时长和条数，不含正文。旧 hud-expired 保留兼容读取，本轮不再把临时隐藏统一记成过期。

## 验证边界

自动模拟覆盖隐藏恢复、同名旧子树、原文字控件短暂缺失、真正过期/销毁、重试上限、迟到结果、槽位复用、精翻更新不重播、控件重建、模式切换和切局。后台隔离测试检查配置兼容、非法值、原因采集、导出隐私及两条请求并发。浏览器使用独立模拟服务检查设置保存、恢复和窄窗口。

固定预算和合成树访问次数不代表实机 FPS。实际游戏左侧位置、分辨率、复杂 HUD、真实淡出及端到端可见性尚需对局复测；不宣称彻底根治所有玩家的漏显。源码修改前保留本地 Git 和源码归档；本轮未自动覆盖个人安装、Steam 启动项或证书。
