# 0.7.3 出装完整源读取测试版

本次将出装翻译的数据来源与游戏面板拆开。优先使用原生 ID、版本及当前可见内容一致的本地缓存；缓存不足时，调用游戏自身的完整出装导出事件，读取 Base64/Zstd/protobuf。生成的源快照包含方案 ID、英雄、版本、分组和装备注释的位置，保存到当前 Windows 用户的 `build-sources-v2`。不写回游戏出装文件，不依赖逐个悬停来补齐内容。

自动导出前复制剪贴板各格式的独立数据句柄，识别并验证游戏导出后恢复；期间用户改动剪贴板时不覆盖其新内容。无法安全保留格式时不自动触发导出，提示玩家手动使用游戏的「复制到剪贴板」。游戏导出使用的副本标题不会写进翻译后的方案名称。

后台按照完整源指纹合并任务，优先处理当前可见的整套方案，再处理玩家手动请求的浏览器列表。关闭界面不取消后台工作，显示原文也不停止新源任务。译文逐字段写入本地缓存，批量结果只重试缺失字段；重启后可以复用源快照和已经完成的译文。悬浮注释只读取当前方案已有译文。

出装浏览器增加「翻译当前列表」，只处理当前已经获取到的标题，保留原始标题供游戏筛选。新搜索结果须重新点击，不会自动翻译整个公共列表；旧结果不能覆盖新一代列表。译文使用独立第二行。

共享 API 读取器对聊天仍使用 2500 字符默认上限；出装批量响应使用独立的有界上限，单字段译文最多 12000 字符。原生 HTML 传输按响应字段数量和字符数分页，再按小帧确认，避免大段说明被标题长度限制截断。

验证入口：

- `dotnet run --project tests/BuildCatalogTests -c Release`：原生 protobuf、KV3、方案鉴别、长译文缓存和响应上限。
- `node tests/build-translation-transport.test.cjs`：原生按钮、源读取握手、延迟导出、方案切换、悬停和大响应分帧。
- `node tests/build-browser-translation.test.cjs`：手动触发、原文筛选、控件复用及新结果隔离。
- `powershell.exe -File tests/native-vpk-identity.test.ps1`：21 项资源及旧包兼容，拒绝不完整或混合 VPK。

实机已确认游戏自动导出、导出后剪贴板文本恢复、公开预览导出与当前已应用方案的 ID 区分、列表按钮触发。最后一次布局修订和响应上限修订尚待同一成套二进制复测，不能用早期候选的画面替代最终验收。未运行真实付费 API 或真实聊天发送测试。测试安装包的构建编号及校验以包内清单和交付目录验收记录为准；正式发布等待玩家验收。

## 2026-11-14 方案切换修订

进度条以界面收齐并显示结果为完成条件。后台结束但仍有结果分页时显示「接收译文」，读取源和等待后台时也保留已经出现的进度条。控件重建后重新绑定标题和说明，按 50 毫秒周期检查已绑定标签，完整面板收集仍按需执行。标题、分组名和可见说明优先于装备注释进入翻译队列。

完整源任务通过快照编号启动，不再把整页可见文本、分组说明重复上传。读取源和结果首包也不再重复携带整套分组说明，缩短原生 HTML 小帧传输在开始翻译和显示首批字段前的等待。

切换检测包含原生版本号和完整标题。完整源快照采用统一指纹，切回已验证方案时复用该指纹对应的全部字段，不重新从第一页接收。没有原生 ID 的切换仍先验证完整源，不能仅凭同名标题、共享分组、相同版本或部分词语恢复旧译文。快速连续导出时，先处理上一次导出的剪贴板恢复，再准备下一次。

新增 `node tests/build-switch-progress.test.cjs`，覆盖结果分页、版本更新、控件重建、A-B-A 切换、读取与排队阶段、共享标题、标题数字变化和同版本内容变化。代码回归不能代替游戏实测。本轮玩家正在正式对局，未操作或覆盖正在运行的游戏；最终修订的界面、时延和快速连续切换仍需对局结束后验证。

## 跨角色及悬浮详情修订

游戏通过本地化模板中的 `selected_hero_build_name`、`category_name`、`category_description` 等变量刷新标题和分组。原位写入原生标签的文本会移除这些绑定。现保留原生标签和模板，以独立译文标签切换显示；源读取始终读取原生文本。控件移动到新的 HUD 根节点时重新关联当前场景并保留手动启用状态。

每份原生布局增加明确的上下文标记。浏览器详情只有位于出装选择器内且不是悬浮提示时才可管理任务；嵌入预览、信息悬浮窗只读取已验证的译文，不能导出、切换任务或显示进度条。商店正文和分组只跟随所属商店的控制器。

导出源的原始标题、ID、英雄和版本独立校验，不能因为 ID 匹配就把另一份导出源改名。读取旧快照时也检查保留的原始 protobuf。已确认错配的旧快照拒绝使用，相关方案的质量缓存切换到单独的修复命名空间；其他方案的缓存保留，原快照保留供检查。

新增 `node tests/build-hero-context.test.cjs` 模拟实际原生变量绑定，覆盖换角色、浏览器选择未完成翻译的新方案、应用后回到商店、悬浮信息窗和 HUD 根节点迁移。`python tests/build-label-bindings.test.py` 检查布局中原生模板及上下文标记。此次实机只读观察显示玩家仍在对局，最终画面和完整复现流程尚未在新二进制上验收。

## 后台崩溃与读取等待修订

沙盒反馈的「正在读取本地整套出装」与后台退出同时发生。崩溃转储记录 `0xc0000374`，栈位于 `KERNELBASE!GlobalSize`。旧代码对所有剪贴板句柄读取全局内存大小；图片等 GDI 句柄及 OLE 内部数据并不是全局内存块。

现按格式分开保存：位图使用 GDI 复制与释放，已知内存格式使用全局内存复制，OLE 内部 DataObject 不作为数据块操作，其他无法确认的格式回退手动导出。后台连接连续失败或读取超时后停止等待，显示原因和「重试翻译」，一次点击即可重新读取。

`python tests/clipboard-native.test.py` 在非交互窗口站中重复 20 轮位图、PNG 和文本恢复，并检查未知格式不被覆盖；测试拒绝使用交互窗口站。初轮沙盒以隔离数据和本地模拟 API 验证当前出装 46/46 完成。成套候选的完整实机结果记录在交付目录，未完成的项目不计入通过。

沙盒还复现了图片多重表示超过备份预算后的手动导出状态续接问题。现优先保留可合成其他位图视图的 DIBV5/DIB，同时保留 PNG 和剪贴板隐私标记，减少同一截图的重复内存。手动／自动标志及截止时间属于后台读取会话，浏览器与商店交接时一并恢复，不能把手动等待误显示成普通读取。
