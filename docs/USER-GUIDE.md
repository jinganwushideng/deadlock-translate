## 接收精翻风格和自己的译文（0.6.22）

## 思考开关、阶段反馈与发送上下文（0.6.17）

“翻译服务→高质量精翻”新增以下选项，修改后保存，对下一批任务生效；“测试 API 连接”使用当前未保存输入，不自动保存。

- **启用模型思考**：默认开启，适合需要消歧的聊天，可能增加等待和 token。关闭倾向响应速度，复杂句可能更易误译；不是准确率保证。
- **思考接口格式**：自动仅识别 HTTPS `api.deepseek.com` 的已知 Flash/Pro 模型。第三方文档支持 `thinking.type` 才选 DeepSeek 兼容格式；“服务默认”不发送开关。未识别时输入检查会提示开关未被发送，实际行为由服务决定。显示“已发送关闭”只说明参数已提交，实际用量以服务返回为准。
- **流式阶段反馈**：默认开启，显示等待、思考、生成和校验。思考阶段需要服务返回相关字段；普通 JSON 响应通常只能看到等待和完成。完整结果通过校验后才显示或发送，不逐字刷新游戏聊天。服务返回普通 JSON 会在同一次请求内处理；拒绝流式参数时关闭后主动测试，不自动重复收费。
- **发送精翻参考近期聊天**：默认关闭，可选 1～3 条、15～30 秒。开启后收集同局同频道新观察的聊天（含中文），只发送选中的近期文本作为精翻消歧参考；按本地观察时间计算，未知频道不混用，跨局清空，草稿提交时固定。会增加发送给云端的聊天数据和 token，可随时关闭。

“诊断与日志 → 最近精翻请求”显示阶段、输入/输出/思考 token、上限、上下文条数、首响应和首译文时间。输出 token 包含思考 token，不要再相加重复统计。缺失用量显示“未提供”，不是 0；缓存命中和词库直接返回不产生新的云端请求。首响应/首译文从进入服务队列起计，包含排队和网络，不是纯模型推理时间。界面只显示阶段与数字，不保存或展示思考正文。诊断 ZIP 包含这些脱敏统计及预算/超时/开关配置。

精翻保留服务默认思考方式。默认输出上限由 2048 提高到 4096 token，可在“翻译服务→高质量精翻→模型输出上限”调整到 512～16384，保存后下一批消息生效；API 连接测试使用当前未保存的输入。预算包含模型思考和最终译文，不是每条固定扣费。保留你已保存的模型、接口和密钥，不附加关闭思考或降低推理力度的参数。

## 专名较多时的精翻性能（0.6.15）

更新后自动生效，没有新增配置项。英雄、装备的明确新旧名字和外号先解析为规范名字，模型不再收到重复的词条解释；尚未解决的歧义和游戏短语仍作为提示。发送仅由名字和标点组成的列表（例如“蓝牛、狼女”）可直接得到“Abrams, Silver”；包含其他字词、时间或数字时仍按你选择的快译/精翻模式处理，不擅自省略战术信息。

网络、模型推理、输出长度或服务限流仍可能使精翻变慢。若稳定遇到慢请求，在设置页导出诊断包：`TranslationTiming` 中 `term-prepare` 是准备耗时，`provider-queue` 是并发等待，`provider-response` 是 HTTP 请求到完整响应（包括网络和服务处理，无法进一步区分）。相同 `Token` 对应同一次请求的各阶段，只是随机匿名标识，不能反推出消息。`Flag=true` 表示发送；`Count` 为提交的用户数据 JSON 字符数，不是实际 token 数或消息正文。`names-local` 表示名字列表本地处理，`Count` 是名字出现次数。缓存命中不产生新的 HTTP 分段记录，整体发送任务日志仍可查看。

后台与游戏 Mod 请通过安装器或外置覆盖更新器成套更新，保留原服务、快捷键、新旧译名和密钥配置。更新不会替你更换模型或开启新的付费通道。

## 快捷键录制与按键选择（0.6.15）

## 0.5.0 安装与连接检查补充

当前游戏要求游戏内网页使用 HTTPS。首次使用需要在退出游戏后运行包内 `Trust-Local-Https.cmd`，核对本机生成的 `DeadlockTranslate localhost` 证书并确认。该操作改变当前 Windows 用户的证书信任设置；私钥由 DPAPI 加密保存，不要分享个人状态目录。**首次信任后必须完整退出并重启 Steam。** 不同电脑分别生成自己的证书。

正常运行使用 `Launch.cmd` 或原有 Steam 启动选项。网页黑屏时用 `Settings.cmd` 打开浏览器设置，在“连接自检”中检查证书、HTTPS 和游戏心跳；“重新检查”不消耗翻译额度，“复制诊断”不含聊天正文或 API 密钥。过期的历史计数不会被当成这次游戏连接。

设置页“发送预留名额”默认开启：启用发送翻译、模型总并发大于 1 时，为发送预留一个名额。总并发 4 时最多 3 个接收精翻并行，发送可立即使用预留名额；关闭预留或关闭发送翻译，接收可使用全部名额。总并发为 1 时使用有公平限制的优先排队。正在进行的请求不会被强行中断。

精翻缓存只匹配相同文本、上下文、模型及词库版本，保存在进程内，不写聊天日志。一个等待者取消不影响其他等待者；全部取消后停止共用请求。不同玩家的重复发言仍分别显示。

证书将在 30 天内到期时会提示。证书过期/损坏时后台保留浏览器设置入口，游戏 HTTPS 暂停；退出游戏并在设置页停止后台后，运行 `Renew-Local-Https.cmd`。续期会备份旧的加密证书，生成新证书并要求重新确认信任，之后完整重启 Steam。续期不更换云端 API Key，也不自动清除旧证书的信任。

本轮没有修改大厅快捷键识别；局内左 Alt＋空格的频道和发送行为保持兼容。

## 1. 这个 Mod 能做什么

- 把游戏里已经显示的玩家文字消息翻译成简体中文，并在原文下方显示。
- 默认处理所有玩家可见发言；可以改为仅队友。它不会获取你原本看不到的敌方队内消息。
- 支持快速翻译、大模型精翻、先快后精三种接收模式。
- 支持左 Alt＋空格，把你输入的消息翻译成英文，再交给游戏发送。
- 发送可选仅英文，或在一条消息中发送“原文 | 英文”。
- 带英雄、装备、技能、俄语名称和常见简称词库，可编辑、导入、导出。

它不翻译语音，不自动回复别人，也不在本机运行翻译模型。除词库直接命中的表达外，翻译服务需要联网；聊天原文及精翻上下文会发给你选用的服务商。

## 5. 日常怎样启动

### 方法 A：使用 Launch.cmd

双击 `Launch.cmd`，程序会先准备翻译后台，再通过 Steam 启动 Deadlock。无需再单独打开设置页。

通过该方式启动后，正常退出游戏约 10–12 秒，后台会随之关闭；如果等待约 3 分钟仍未启动游戏，后台会结束等待。若只是单独运行 `Settings.cmd` 配置服务，后台可以保持运行，直到你在设置中停止它。

### 方法 B：直接点击 Steam 的“开始”

只需要设置一次：

1. 打开 Steam，进入“库”。
2. 右键 Deadlock，选择“属性”。
3. 在“通用”页面找到“启动选项”。
4. 找到你的 `DeadlockTranslate.exe`，确认它的完整路径。
5. 按下面格式填写启动选项：

```text
"D:\DeadlockTranslate\DeadlockTranslate.exe" --steam-game %command%
```

6. 关闭属性窗口，再点击 Steam 的“开始”。

注意四点：

- 引号内必须是 **你自己的 EXE 完整路径**，不是游戏 EXE，也不是 VPK。
- 使用英文半角双引号，保留 `--steam-game %command%`，不要给 `%command%` 额外加引号。
- 普通原有游戏参数应保留在 `%command%` 后。若原来已有另一个带 `%command%` 的启动器，不要直接叠加，先请对方或本 Mod 作者协助合并。
- 安装包旧开发文档中可能出现开发者电脑上的 `G:\…` 路径，那不是你电脑的固定安装位置，不能直接照抄。

设置好后，Steam 创建的该游戏快捷方式也可沿用这一入口。没有另加登录自启项或常驻游戏监测器。

## 6. 在哪里打开设置

**游戏外：** 双击 `Settings.cmd`，打开系统浏览器设置页。

**游戏里：** 按 Esc，在游戏“设置”附近点击“翻译设置”，打开内嵌窗口。

- 改完配置等待顶部显示“所有更改已保存”；失败时先重试或处理冲突，草稿会保留。
- 用窗口标题栏的“关闭”或 Esc 关闭；点击外侧遮罩不关闭窗口。
- 游戏内窗口不会暂停 PvP 对局，适合在安全时机调整。
- 游戏内窗口仍在做兼容性验证。如果出现不能点击、不能输入、空白或连接提示异常，先使用 `Settings.cmd` 配置，并把具体表现反馈给作者。

外框的“尚未收到页面状态”不等于后台一定没启动；页面初始化失败、与后台断连、云端模型调用失败也是不同的问题。

| --- | --- |
| 仅快速翻译 | 走快速服务，响应优先 |
| 仅高质量精翻 | 使用你配置的大模型，可能需要等待 |
| 先快译，再精翻 | 先显示快译，再原位更新；精翻失败保留已有快译 |

默认显示游戏里所有玩家的可见文字聊天，包括自己、友军、全体及组队内容。只希望翻译队友时，选择“仅队友”。系统提示、Ping、聊天轮盘及已是中文的消息可能不会再请求翻译，这是正常过滤。

原文保留，译文只在你本机显示，不会因为接收翻译而自动向其他玩家发送任何消息。

## 8. 左 Alt＋空格翻译发送

1. 先用游戏自己的按键打开所需聊天频道。
2. 输入要说的话；中文输入法的候选词要先确认，确保文字已进入聊天框。
3. 按 **左 Alt＋空格**，不是右 Alt。
4. 聊天框收起后继续游戏，后台完成翻译后提交消息。

游戏中的三个频道要分清：

| 游戏输入框提示 | 设置页名称 | 含义 |
| --- | --- | --- |
| 对（友军） | 友军 | 本局友方队伍 |
| 对（队伍） | 队伍（组队） | PARTY 组队频道 |
| 对（所有人） | 全体 | 所有人可见频道 |

普通 Enter 仍按游戏原有方式发送原文，不触发这个组合键功能。选择“自动”发送引擎，只是自动选择精翻或快译，不是自动回复别人。

“发送内容”有两种：

- **仅英文**：例如只发 `Hello`。
- **原文 + 英文**：例如一条消息 `你好 | Hello`，不是分开发两条；同一句原文不因此多调用一次翻译。

默认同时保留 12 条待发送任务，可在“发送翻译”调到 3–32 条；发送翻译默认 3 路并行，可调 1–8。单条内容有 80 个 Unicode 字符限制；超长时按“超长内容自动分条”开关处理，关闭时尽量填满单条容量并发送前缀，余下不续发；完整原文和译文仍保留，最近任务显示未发送字数。翻译期间如果你又开始编辑新消息，会等待并保护新草稿。频道无法确认时保留原文，不改发到其他频道。

不要因为没立即看到英文就反复按快捷键；先到“发送翻译 → 最近发送任务”检查状态。

## 9. 怎样看“最近发送任务”

| 状态 | 含义与处理 |
| --- | --- |
| 等待翻译 / 翻译中 | 正在排队或请求服务，先等待 |
| 等待游戏提交 | 译文已生成，游戏端尚未提交；可能正在编辑另一条消息 |
| 等待频道确认 | 当前原生目标与任务未确认一致，不会改发全体 |
| 等待前一条发送 | 译文已完成；为保持同一频道的说话顺序，等待前一条提交或失败 |
| 已交给游戏 | 已调用原生提交；最终是否送达仍以实际聊天记录为准 |
| 未发送 | 已失败或过期，看下面“原因”，不会再自动补发 |

“保留内容（未发送）”只是用于复制的已生成文本，不表示仍会自动发出。“发送队列已满”通常是连按太快或此前有任务尚未完成；等待任务结束或过期，不要继续连按。

关闭发送翻译开关会在下一次同步后取消未提交任务，已经交给游戏的消息无法撤回。复制保留内容后，可以自行粘贴到正确频道并用普通 Enter 发送。

## 10. 字号、显示和性能

“显示与性能”可调整译文字号，预览区会随之变化。译文默认使用纸色底、深色字；专名可显示为“中文（English）”。

消息检查间隔默认 200 毫秒。间隔越短，检查越频繁；没有必要为了云端翻译速度把它调到最小，因为网络和模型延迟仍然存在。并发数、超时可在页面允许的范围内调整，先保留默认值即可排查整体功能。

### 多人连续发言时的高频配置

在“显示与性能”点击“填入高频配置”，等待自动保存：快速服务总并发 4、大模型总并发 4、发送翻译并发 3、待发送容量 12。并发上限最多 8，容量最多 32；它们都可以单独调整，旧配置不会因升级自动丢失。

接收、发送和试译共用相应的服务总上限。例如大模型总并发是 4，就不是接收 4 条再额外发送 3 条，同时占用最多仍为 4 条。发送还受自身并发限制；各条译文可以同时生成，但同一频道按输入顺序交给游戏。

概览中的并发/排队计数有助于判断积压。提高并发不等于加快单次模型思考；服务商也可能限流。出现 HTTP 429 后会遵守服务冷却，不会持续重试，必要时降低并发。调低上限时已开始的请求会正常结束，因此短时间内正在运行的数量可能仍高于新上限。

若游戏消息一直无法回传，可试“游戏桥接方式 → 页面导航 · 兼容模式”，保存后重启游戏再测。它是兼容选项，不保证更快。

游戏内设置窗口打开时会增加页面渲染工作，关闭时程序会卸载它。实际帧率与显示效果因游戏版本、分辨率和其他 Mod 而异，自动测试不能代替实机检查。

## 12. 常见问题

### A. 双击程序后看不到窗口

后台本来就不显示独立控制台。要配置请运行 `Settings.cmd`；要一起启动游戏请运行 `Launch.cmd`，或使用已配置好的 Steam 入口。不要仅靠“有没有黑色窗口”判断运行状态。

### B. 设置页面提示后台未连接

先运行 `Settings.cmd`。浏览器可访问下面的只读健康检查地址：

```text
http://127.0.0.1:17865/health
```

正常时会看到程序名、版本等 JSON。如果能访问，但游戏内外框仍提示未连接，更可能是嵌入页面或状态回传问题；使用浏览器页配置并反馈。健康检查正常不代表云端翻译服务也一定正常。

### C. 只有关闭、刷新能点，网页里的按钮不能点

这是游戏内 HTML 页面兼容问题，不要因此反复重填密钥。先确认后台和 VPK 来自同一最新版安装包，并且更新后重启过游戏；临时使用 `Settings.cmd`，把游戏内具体表现反馈给作者。

### D. 英文译文生成了，但消息没发出去

检查“最近发送任务”的实际状态和“原因”，并区分友军与组队频道。不要只看到保留文本就认为还在等待自动发送。长消息、频道不一致、超时、队列已满都可能导致未发送。

### E. 快捷键不起作用

确认开启了发送翻译、Deadlock 在前台、聊天框已打开且文字已输入完成，使用左 Alt。若“快捷键监听未启动”，先停止后台再通过启动入口重新运行。若其他软件占用同一组合键，先处理那一处冲突。

### F. 模型请求失败、限流或超时

检查 API 地址、模型名、密钥对应的服务/套餐和剩余额度。先保存，再用完整句子试译。一次失败不能证明游戏 Mod 没加载。Bing 免密钥失败时可稍后重试或自行配置其他服务，不要盲目提高并发或频繁重复请求。

### G. Steam 点“开始”后启动失败

检查启动选项里 EXE 路径是否仍存在，是否使用英文引号，以及 `%command%` 是否保留。不要填作者电脑路径。可以先恢复原启动选项，确认原版游戏能启动，再检查 Mod 安装和 `Launch.cmd`。

### H. 安装提示已有安装记录

不要删除记录强行反复安装。先使用原版本的 `Uninstall.cmd` 卸载本 Mod，再安装新包。安装记录用于确定本 Mod 的 VPK 和恢复原配置，不能复制别人电脑的记录来代替。

### I. 更新游戏或安装其他 Mod 后翻译不见了

游戏更新可能改变资源或还原加载配置；其他 Mod 也可能覆盖聊天布局。保留报错和冲突列表，关闭游戏后检查本 Mod 安装状态。不要把旧 `gameinfo.gi` 整个覆盖到新游戏版本上。

## 13. 升级与卸载

### 升级朋友的安装

1. 退出 Deadlock，Steam 可以保持打开。
2. 将新版完整运行 ZIP 和外置 `覆盖更新.cmd` 放在同一文件夹，不必手动解压或复制到旧目录。
3. 双击外面的 `覆盖更新.cmd`，等待“覆盖更新完成”。它会自动选包、解压、定位旧安装和成套替换游戏 Mod 与后台；若需要选择目录，选 Steam 启动选项原来使用的 EXE 所在文件夹。
4. 按原方式启动，检查版本、服务配置和词库，再进入游戏测试。

更新不会改变 Steam 启动路径、API 密钥、配置或证书。临时解压内容自动清理，备份保留；完成后下载的 ZIP 和外置更新器可继续保留或自行移走，原程序目录继续使用。不要仅替换 EXE 或 VPK。没有安装记录时不能使用覆盖更新：首次安装请手动解压后运行 `Install.cmd`；旧记录丢失时先联系维护者确认原 VPK，避免重复安装。

### 不想继续使用

1. 退出 Deadlock。
2. 在 Steam 启动选项中删除本程序的 `"…DeadlockTranslate.exe" --steam-game %command%` 部分，恢复你原来的普通游戏参数。
3. 在设置页停止后台，再运行 `Uninstall.cmd`。
4. 卸载成功后才移动或删除解压目录。

卸载只处理本 Mod 记录的文件，配置和密钥默认保留。如果安装后的 VPK 或 `gameinfo.gi` 被其他工具改过，卸载器可能拒绝删除或保留文件并给出提示；请记录提示，不要批量删其他 Mod。

## 14. 配置在哪里，哪些不要分享

个人配置通常在当前 Windows 用户目录：

```text
%LOCALAPPDATA%\DeadlockTranslate
```

其中可能包含 `settings.json`、`secrets.dpapi`、`terms.json` 和本机安装记录。密钥由 Windows DPAPI 保护，与用户环境有关，不应复制给朋友使用。

分享时只发作者提供的完整发布 ZIP。朋友自己安装、填写自己的接口与密钥。不要把自己的个人配置目录、安装记录或服务商密钥打进去。默认不持久保存聊天正文；服务运行期间仍会在内存中保留当前任务，精翻会使用相关近期聊天上下文。

## 15. 反馈问题时提供什么

提供版本、具体操作步骤、是哪一个聊天频道、能否打开浏览器设置、最近发送任务的状态/原因，以及是否安装了其他聊天或菜单 Mod。

游戏内窗口的问题请说明：页面是否显示、哪些按钮能点、输入是否有效、关闭后是否恢复游戏操作。可以提供遮住私人信息的截图。**不要发送 API Key、包含登录令牌的完整设置页地址，或整个个人配置目录。** 只报告 `http://localhost:17865` 这样的主机与端口即可。

当前游戏内窗口仍需在不同电脑与游戏版本验证；编译、浏览器测试、自动回归通过，不等于所有机器的游戏内交互都已验证。

## 管理员游戏与连接排查（0.6.5）

普通权限运行游戏时使用原入口即可。只有游戏需要管理员权限时，才选择以下入口之一；不安装额外常驻服务，也不默认改变 Steam 权限。

1. 双击程序目录的 `Launch-Admin.cmd`，由原 Windows 用户确认 UAC，随后正常启动游戏；已有证书无需重新安装。
2. 在翻译设置 → 发送翻译中点击“管理员兼容重启（需 UAC）”，确认 Windows 弹窗后重新加载游戏内窗口；浏览器用户重新打开 `Settings.cmd`。先完成或复制待发送任务，重启会取消它们，不补发旧消息。
3. 希望以后直接通过 Steam 使用兼容模式：在设置页点击“复制 Steam 管理员兼容启动项”，退出游戏后粘贴到 Steam → Deadlock 属性 → 启动选项。格式如下，路径必须替换为自己的真实程序路径：

```text
"D:\DeadlockTranslate\DeadlockTranslate.exe" --admin-compatible --steam-game %command%
```

`--admin-compatible` 必须放在 `--steam-game` **前面**。原来 `-novid` 等普通游戏参数放在 `%command%` 后面。每次启动会请求 UAC；拒绝确认则不会启动翻译后台。退出兼容模式时只移除 `--admin-compatible`，保留原翻译启动项。`Configure-Steam.ps1 -AdministratorCompatibility` 可生成/写入兼容模式；`-NormalPermissions` 明确恢复普通模式，不带这两个参数则保留现有权限选择。

必须使用安装时同一个 Windows 用户。UAC 若要求输入另一个管理员账户，请取消；本程序会拒绝跨账户接管，避免 DPAPI 密钥、证书信任和安装记录错位。后台已具有管理员权限时，不会再次请求 UAC。程序不关闭 UAC、不修改安全策略、不自动提权、不安装 watcher。

游戏接收翻译/设置页连接与快捷键权限属于两条链路：权限不一致不能说明证书一定有问题。检查设置首页的证书状态和游戏请求状态，再使用一键导出日志。已有证书有效且已受信任时不重装；缺少 `pairing.key`、后台/VPK 来自不同版本、旧后台占用端口或不同目录启动时，先成套更新并停止旧后台，不要删除密钥或覆盖其他 Mod。

游戏桥继续使用 HTTPS。`localhost` 初次加载失败后，以 5 秒间隔尝试证书 SAN 中的 `127.0.0.1` 地址；不会改用 HTTP 或跳过证书验证。设置窗口首次优先使用桥接成功的地址，手动“重新加载”会尝试另一回环地址。证书未信任、过期或另一用户没有信任仍需正确修复，地址重试不会绕过这些问题。

启动错误会显示固定提示并记录分类/Win32 错误码，不输出密钥、聊天或异常原文；取消 UAC与需要管理员权限分别识别为 Windows 1223/740。端口被其他程序占用时不关闭它。两个后台的用户、数据目录、程序目录、配对和版本全部一致才允许复用；管理员兼容切换会等旧后台正常退出，不强杀进程。

如果路径已经正确、修复后仍报错，可能是默认配置文件缺失/损坏或其他启动路径问题。先备份自己的额外游戏配置，再通过 Steam → Deadlock 属性 → 已安装文件 → 验证游戏文件完整性。校验后重新运行修复入口以恢复需要的 Mod 挂载；不要删除整个 cfg 文件夹。可提供报错括号中的完整文件名和 SearchPaths 区块继续判断。

## Bing 网页能打开，但快译返回 HTTP 302（0.6.12）

302 表示跳转，可能出现在获取网页凭据或调用翻译接口时；网页能打开不等同于免密钥请求成功。0.6.12 会处理 HTTPS 官方 Bing 翻译地址之间的区域跳转，凭据页最多跟随 3 次，翻译请求最多重新取凭据后重试一次。Origin、Referer 和请求使用凭据所属的同一官方地址。

验证/登录页、其他站点、非 HTTPS、自定义端口或循环跳转会停止，并显示具体服务、HTTP 状态和阶段。不会复制浏览器 Cookie、自动绕过验证或自动切换付费服务。大模型和 Azure 请求继续禁止自动跳转，避免把密钥发给跳转目标。

遇到提示时，在同一台电脑的 Bing 网页实际输入一句话试译，检查是否要求验证。持续失败可自行配置正式 API 或大模型，再选择对应引擎测试。请先成套更新到本版，分别测试“快速翻译”和“高质量精翻”；仍失败时导出新的诊断包。日志包含服务名、HTTP 状态、请求阶段和错误类型，省略文本、密钥、Cookie、完整地址和跳转查询参数。


## 0.6.12 补完：API 输入检查与连接诊断

在“翻译服务”的大模型或 Azure 卡片中选择：

- **检查输入（不联网）**：只检查当前输入格式，显示实际请求端点，并标记应修改的地址、模型 ID、密钥或区域；不会验证服务是否真的存在。
- **测试 API 连接 / 测试 Azure API**：先本地检查，再用固定诊断句测试，不含游戏聊天，也不自动保存输入。可能消耗少量服务额度，成功后需点击“保存设置”才能用于游戏。

密钥留空仅沿用该服务已有密钥；如果没有已保存密钥就提示缺失。换到另一服务地址时，必须提供对应密钥，不默认带旧密钥测试。不要填写 Bearer 前缀或整段请求头。模型必须是完整接口 ID，前后空格、隐藏字符和疑似复制到模型栏的密钥会提示。

地址可填 BaseURL 或完整 Chat Completions 端点，程序会显示最终地址供核对，不统一猜测是否需要 /v1。Anthropic、Responses、模型列表、登录/控制台/文档入口不能混用。远程接口要求 HTTPS，本机接口允许 HTTP。

联网结果会区分：401 鉴权失败、明确模型不存在/未授权、模糊 404 的地址或模型问题、402/特定错误码的额度不足、429 频率限流、403 权限/资源问题、协议/参数拒绝、DNS/TLS、网络超时和服务端故障。模糊响应会明确说明证据不足。HTTP 200 但没有兼容格式的文本，也不显示“测试通过”。

结果是这次请求的证据，不能保证以后额度/网络/翻译质量。输入改动后旧结果失效。旧 0.6.12 若缺少诊断接口，请用同版本补完版成套覆盖更新并重启后台；仅替换网页无法加入新接口。诊断日志和导出包继续排除地址、模型名称、密钥、服务响应原文与测试正文。

## 三条接收消息自动触发并发（0.6.18 补完）

接收按“同一局尚未完成的消息”计数，包含正在处理和排队的消息。第一条立即开始；只有 1～2 条时快译、精翻各自按 1 路处理，二者保持独立；达到 3 条就放开到服务设置的并发上限。第三条稍后到来也立即触发，不需要同一批到达，不会为了凑满三条故意延迟。

混合模式一条消息的快译/精翻两阶段合计只算一条未完成消息，直到需要的阶段全部完成才退出计数。上下文专用记录、暂停跳过和重复提交不计数。未完成数量降到 3 条以下时只限制后续请求，已开始的不会取消；再次达到 3 条又可立即并发。

这里的“达到 3 条”包含恰好 3 条；不足 3 条时同样正常翻译。并发上限仍以你设置的快速/大模型服务总并发为准，接收/发送共用总额度，大模型发送预留也继续生效。上限设成 1 时，即使触发也仍只有 1 路；若想同时接收精翻三条，通常需要总并发至少 3，开启发送预留时至少 4。不会自动改你的上限或关闭预留。

概览的排队状态会显示“接收逐条/并发（未完成 X / 触发 3）”；服务页说明调度规则。发送翻译和试译不受这个接收阈值限制。普通服务超时和限流仍生效，并发减少排队，不会加快模型本身的单次响应。日志导出状态中 receiving 包含 threshold、unfinished、burst、fastLimit 和 qualityLimit，均为数字/布尔值，不包含消息内容。


安装器现自动忽略已识别的 QOL LOCK 包，不再因为 QOL 自带聊天功能或气泡样式而要求停用/确认共存。此规则同时用于安装、更新和缺失 VPK 恢复，QOL 文件保持原样；其他 Mod 继续检查。版本仍为 0.6.18，请使用含 qol-compatible 标记的完整包。
