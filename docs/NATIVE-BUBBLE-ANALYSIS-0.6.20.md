# 0.6.20 原生气泡漏显：证据、修订与验收

## 已有实机证据

上一轮单标签合成缓存候选，在 2026-10-17 00:19～00:20 的 8 条测试中全部翻译成功，其中 6 条缓存命中，另外两条约 2 秒。随后一局的 12 条也全部完成，无服务失败，全部有原生写入和正尺寸记录。两轮用户都报告原生气泡漏显。

标签读回译文正确，就绪状态为 true，自身透明接口返回 false；旧固定标记均为 135。这只能证明标签对象的状态，不能证明最终像素，也没有测到祖先实际裁剪矩形。缓存命中仍漏显，说明模型等待不是该显示故障的充分解释。

匿名原始证据分别位于 artifacts/native-composition-live-evidence.json 和 artifacts/native-composition-second-run-evidence.json。它们没有聊天正文、玩家名称或 API 密钥。

## 拆开的两个问题

1. **透明占位是确认的布局缺陷。** 旧 CSS 使用 opacity:0，同时设置 width/min-width:220px 和 min-height:20px。透明不会取消布局占位，标签会改变 MessageContents 的期望尺寸、行距及气泡排列。旧方案为避免零尺寸而保留了这个空槽，但它既影响外观，也没有消除漏显。
2. **跨界面更新是待验证的故障点。** 控件在原生 ChatMessage 模板内创建，但赋值、样式更新一直由 chat.xml 的脚本执行。预建控件解决了一部分零尺寸问题，却没有改变最终更新的执行环境。Tab 或切窗后恢复符合更新失效的表现，但不能据此断言引擎根因。

离线检查本机原生资源和 client.dll：CitadelHudTopBarChat 加载自己的布局，并有单独的气泡排列代码，读取 ChatArrow 与 MessageContents，再安排消息。仅看到子控件尺寸变化不能确认最终排列与绘制都已更新。本项目不修改、注入或运行 DLL 中的代码。

## 当前候选修订

- 保留引擎预建译文 Label；收到译文前 visibility:collapse，不放可见占位、不预留最小高度，宽度改为 fit-children 并保留 220px 上限。原文、头像、箭头及其父子顺序不变。
- 使用本机 Panorama 提供的 RunScriptInPanelContext，把最终文本变量、字号、透明度和展开操作交给目标 Label 的环境执行。这个接口在当前引擎有原生实现及来源检查，实际调用结果仍需游戏验证。
- 执行的脚本由本项目固定函数生成一次；原文和译文通过临时字符串属性作为 JSON 数据传递，绝不拼接进脚本、HTML 或命令。执行和拒绝后均清空传输属性。
- 目标脚本重新核对标签类型、直接宿主、原文、原生消息标识、原生 Expired/祖先隐藏状态。目标执行结束后写入序号回执；调用返回但没有匹配回执，不记作写入成功。
- 不支持、拒绝或抛错时保留折叠，不回退到旧的跨环境赋值。相同状态最多两次连续失败尝试，记录明确阶段；游戏聊天记录和独立栏仍可显示结果。
- 移除已被实机否定的有限亮度动画和强制 ApplyStyles；移除单标签强制合成/禁用缓存属性。不修改父容器高度、不重挂原生控件、不使用坐标翻译层或模拟按键。

## 新日志能回答什么

| 阶段或字段 | 含义与限制 |
| --- | --- |
| hud-context-applied | 收到目标序号的成功回执；仍不是 GPU 可见证明。elapsedMs 为整个目标调用的实际用时。 |
| hud-context-unavailable | 接口缺失、调用抛错或没有匹配回执；不把普通返回当成功。 |
| hud-context-rejected，count=3 | 原生气泡已过期，或祖先/原文处于隐藏状态。 |
| 同上，count=4 | 原文或原生消息标识已变化，拒绝把旧结果写到新消息。 |
| 同上，count=5 | 宿主结构、标签类型或输入边界不符。 |
| 同上，count=6 | 目标执行过程出现异常；不记录异常正文。 |
| ancestry | 最多 8 级的固定数字状态；不记录任意控件 ID、玩家名称、文本或图片。 |

成功更新时采一次上层状态，并在已有扫描回调中约 200ms、约 1000ms 再采样。突发时可能因队列预算而稍晚；没有为每条消息新增定时器。稳定标签不会持续采样。最多保留 64 个检查项，每次回调最多检查两项；渲染仍按两条记录的预算执行。

ancestor.role：0=其他，1=译文标签，2=MessageContents，3=ChatMessage，4=Messages，5=队伍气泡根，6=ChatContainer，7=TopBar，9=已知游戏根。level 为距译文标签的父级层数。缺失的级别并不代表该容器不存在，只可能超过 8 级或不可读取。

ancestor.flags：1=visible为false，2=本级可读样式为隐藏/折叠，4=Expired，8=gScoreboardOpen，16=gDetailView，32=就绪接口存在，64=就绪为true，128=透明接口存在，256=透明接口返回true。

width/height/x/y 是可读取的局部布局值；opacity 是可读取的本级样式值。未读到的值为 null，不能当作默认值或“完全可见”。overflow：0=未知，1=clip，2=noclip，3=scroll。局部边界不等同于最终经过缩放/变换的屏幕裁剪矩形；这些日志用于找变化点，不据此直接宣称遮挡已排除。

## 如何验收与继续定位

1. 成套安装后台、设置页和 VPK 后，核对 featureRevision 末尾为 hud-native-panel-context-compact-candidate。
2. 发短句、长句、重复缓存句及连续消息。不按 Tab、不切窗、不额外开关聊天框，观察原生译文是否自行出现；原文在译文未到时不应被透明空槽撑开。
3. 若仍漏显，先看目标回执。缺失或拒绝可定位到接口/执行环境/消息生命周期，不再归结为服务慢。
4. 若回执成功，比较成功与失败消息的三次祖先状态，检查是否出现某一级零尺寸、透明、隐藏或越界。可再由用户对仍存活的失败气泡按一次 Tab，核对恢复表现；日志没有画面像素，不能据“状态全正常”认定修复成功。
5. 若仍无差别，再做保留备份的纯翻译 VPK 对照或经用户允许使用原生调试器读取计算样式。未取得对照证据前，不认定 QOL 或其他 Mod 是原因。

## 性能与验证边界

新增工作发生在结果/外观变化和有限采样时。没有每帧全树扫描、截图识别、持续动画、全局缓存开关或额外后台。同步的目标脚本编译/执行及祖先读取仍有成本；elapsedMs 与 maxScanMs 可帮助量化下一次实机开销，但不等同于游戏帧率。

测试在独立 JS VM 中执行实际目标函数，验证作用环境、数据隔离、回执、失效拒绝、隐私和预算；控件尺寸由测试桩提供。原生资源编译/反编译、后台导出和文件校验也不模拟真实 GPU。最终像素、长句排列、原生淡出、连续消息和 FPS 都必须游戏内验收。
