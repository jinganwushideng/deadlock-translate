0.2.3 修复频道误判、等待任务无法恢复和聊天回显误报；复查还修复了关闭发送后排队任务仍发送、后台重启遗留热键读取新草稿的问题。发送前必须读到明确的原生频道，标签文字不能授权发送；不支持该原生属性时保持等待，最终过期并保留原文。详见 `REVIEW-FIX-0.2.3.md`。包内 0.2.2 文档属于历史记录。

## 从 Steam 直接启动

0.2.5 支持把现有翻译程序作为 Steam 的启动入口，不需要额外常驻监测程序。Steam → Deadlock → 属性 → 通用 → 启动选项中填写：

```text
"G:\Deadlock翻译mod\DeadlockTranslate-0.1.0\DeadlockTranslate.exe" --steam-game %command%
```

上述路径对应本机安装位置，目录名中的 0.1.0 为兼容保留的旧名称。如移动安装目录，必须同步修改这一项。已有普通游戏参数应保留在 `%command%` 后；已有其他 `%command%` 包装器时先合并方案，不可直接覆盖。

Steam 点“开始”后，翻译程序先启动本地服务，然后执行 Steam 传来的原版游戏程序及参数，保留 Steam 环境变量与工作目录。不会再次调用 Steam 游戏 URI，不会形成启动循环。游戏正常退出约 10–12 秒后翻译后台退出。之前已经打开设置后台时，Steam 拉起的临时第二实例只负责启动游戏，随后立即退出，继续使用原有后台。

取消本联动或卸载 Mod 前，删除启动选项中的 `"...DeadlockTranslate.exe" --steam-game %command%` 前缀，恢复原有游戏参数；否则 Steam 会继续尝试运行已经移除的翻译程序。普通 `Launch.cmd` 仍可使用。原理参考：[SteamWrap 的 Windows 实现](https://github.com/qjimbo/SteamWrap)。本机实际游戏内表现仍由用户验证。

## 使用

1. 关闭 Deadlock，运行 `Install.cmd`。安装器自动定位 Steam 游戏目录，扫描冲突，选择空闲 VPK 槽位。遇到相关聊天/HUD Mod 时会列出名单；只有你输入 `YES` 才继续。精确覆盖相同资源时停止安装。
2. 运行 `Settings.cmd` 打开系统默认浏览器设置页。Bing 快译无需密钥；LLM 填写兼容 Chat Completions 的地址、模型名和密钥。先点击“试译”确认网络可用。
3. 运行 `Launch.cmd` 启动后台和 Deadlock，或使用已配置的 Steam 启动入口。按 Esc，在原生“设置”下方点击“翻译设置”打开游戏内窗口。入口通过追加控件实现，不覆盖其他 Mod 的 Esc 菜单布局。
4. 默认翻译游戏里已经显示的所有玩家文字聊天：队友、敌方全体聊天、自己，以及身份未知但结构明确的玩家消息。分别读取普通聊天、HUD 气泡和旧式大厅聊天。原文保留，译文在下方更新，仅自己可见。只想看队友时，在设置页把“翻译范围”改成“仅队友”。系统提示、聊天轮盘、Ping 和已经是中文的消息仍由游戏本身处理，不重复请求。

配置好上述启动选项后，可直接从 Steam 或 Steam 创建的游戏快捷方式启动，无需提前运行设置页。无需安装 .NET，无开机自启，无独立桌面窗口。后台可从设置页停止。

## 左 Alt＋空格发送英文

在队伍或全体聊天框输入文字，按左 Alt＋空格。程序收起聊天框，后台翻译完成后把消息交回原生聊天输入框并触发原生提交事件，发送到按键时的频道，不使用控制台 say 命令。普通 Enter 的原文发送保持不变。

“发送内容”可选“仅英文”或“原文 + 英文”。双语始终是一条普通消息 `原文 | 英文`，不会发两条，也不会额外调用一次翻译；原文与英文规范化后相同（忽略大小写）时只发一份。按键时的模式会随任务保存，排队期间改设置不影响已排队的任务。原文与英文合计超过 500 个字符时不发送、不截断，原文仍可复制。

为避免干扰操作，如果你正在编辑下一条消息，程序会等到聊天关闭再提交，并保留草稿。程序不主动打开聊天框、不模拟粘贴、不抢焦点。发送前会确认真实频道：优先读取游戏的原生目标属性，读到队内才按队内发送；确认不了时保持“等待频道确认”，超过发送期限标记失败并保留原文，**不会改发全体**。发送后的一次有界回显观察如果发现频道标记不一致，会暂停后续发送并在设置页计数，避免继续公开喊话。

设置页的“发送翻译”可开关此功能、选择发送内容、选择自动/快译/精翻、设置总超时以及剩余时间内的失败回退。自动模式在配置了 LLM 密钥时使用精翻，否则使用快译。仅识别左 Alt；后台热键监听只在 Deadlock 前台且聊天输入激活时消费空格组合，不读取其他按键文字。

默认保留 12 条待发送任务，可在设置中调整到最多 32 条。翻译并行进行，实际提交在同一频道内保持先后顺序。过期、跨局或失败时不补发；最近发送面板保留本次会话内的原文、英文和待发送文本供复制重试。“已交给游戏”表示已调用发送命令，不等于服务器确认送达。

## 服务与术语

- Bing：免费网页接口。页面令牌会过期，程序按需刷新；限流后冷却，不自动切换付费服务。
- Azure Translator：正式 API，需要密钥及相应区域。
- LLM：支持 `base URL`（例如 `https://api.scnet.cn/api/llm/v1`）或完整 `/chat/completions` 地址。可使用 `DeepSeek-V4-Flash-0731-Event` 等兼容模型。程序不会附加 `复制` 等网页按钮文字。
- 401 代表服务认证失败；429 代表限流；精翻超时会保留快译结果。默认快译 5 秒、精翻 30 秒超时。
- 初始词库来自本机游戏中英文英雄与装备资源，加上手工维护的英俄短语。完全命中已审定短语时，两种模式都直接返回词库译文，减少等待和请求。明确专名附带英文；Seven、Pocket 等歧义词不会在快译中强行当作英雄替换。词库可搜索、编辑、导入和导出。

## 性能与兼容性

每 200 毫秒检查各普通聊天容器和大厅聊天末尾至多 24 条记录、每个 HUD 容器末尾至多 12 条。只在发现或恢复容器时搜索界面根节点。不同显示位置中同一条消息会尽量共用翻译任务；同位置的重复消息仍作为独立消息。单次回调最多更新 2 条记录，译文非逐字流式显示。

默认复用一个隐藏网页，使用片段导航收发批次。首次片段通信失败时尝试兼容导航模式。导航模式的开销可能更高。后台网络异步处理，以低于正常的进程优先级运行。

Node 模拟扫描时间和后台 CPU 占用不能证明游戏帧率没有变化。当前版本没有完成真实对局的平均 FPS、1% Low 和帧时间测量。

只有可靠识别本地队伍或消息的友方标记时才翻译他人的顶部气泡，不依赖普通聊天列表先出现对应消息。“翻译范围”设为“仅队友”时，身份不明的消息保守跳过，设置页显示读取和跳过计数；默认的“所有玩家”不再要求先知道本地队伍，只要求消息结构、正文和消息类型明确。跨视图的角色可能一边未知、一边敌方，这类同一句话继续共用一次翻译；队友与敌方冲突时不合并。精翻上下文按频道分开保存（队伍与全体各自最多 6 条、60 秒），没有已知频道时只使用当前消息。聊天记录清空不再被误判为换局；跨局适配依赖界面生命周期及有效比赛标识。

## 配置、安全和卸载

配置位于 `%LOCALAPPDATA%\DeadlockTranslate`。服务商密钥通过 Windows DPAPI 加密，不能直接迁移到另一 Windows 用户。默认不保存聊天正文，只保存运行计数。精翻会发送当前消息、相关术语和最多 6 条、60 秒内的上下文到你配置的服务商。

本地端口为 `17865`，仅绑定回环。`pairing.key` 是游戏 Mod 与后台的本机配对标识，不是服务商密钥；它与安装包中的 VPK 必须匹配。浏览器设置使用每次启动重新生成的会话凭据。

运行 `Uninstall.cmd` 只卸载本安装器记录的 VPK，校验哈希后再删除。其他 Mod 保留。若安装时修改过 `gameinfo.gi`，且文件之后未变更，则恢复安装前内容；否则保留当前文件和备份供人工处理。翻译设置和加密密钥保留，可在设置页清除密钥。

## 源码与构建
