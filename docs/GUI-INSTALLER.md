# GUI 安装、更新与维护（0.7.0）

使用 `DeadlockTranslate-Setup-0.7.0.exe`。它内置完整 Windows x64 程序和游戏 Mod，可离线安装，不需要另下 ZIP、运行 PowerShell 命令或安装 .NET。翻译服务本身仍需要联网。

## 更新日志

安装器底部有独立的“更新日志”按钮。默认显示当前包的功能简记，版本下拉框可查看旧版记录；内置 30 个版本，0.4.0 明确标记为源码记录。离线可看，不需要后台、证书或初始化检查成功；只读查看不执行安装。

每个新版本都要在 docs/UPDATE-HISTORY.json 中追加本版简记，保留旧条目；构建会校验其与 version.json 和 CHANGELOG.md 的版本集合、顺序及内容格式。详细记录仍随运行包 CHANGELOG.md 提供。

## 首次安装

1. 退出 Deadlock，以平时运行 Steam 的 Windows 用户双击安装器。先选“安装 / 覆盖更新”。
2. 第 1 步检查证书。本人请留在电脑前，点击“准备 / 信任证书”，核对名称 `DeadlockTranslate localhost`，在 Windows 弹窗确认信任。没有确认则停止，不继续安装。有效且已受信任的证书无需重装。过期/私钥缺失时可明确选择续期，旧证书先备份；不要更换 Windows 账号以免旧密钥无法解密。
3. 选择游戏和程序目录。默认从 Steam 库和已有记录定位；多份游戏由你选，支持粘贴游戏根目录、`game\citadel` 或游戏 EXE。深层扫描需明确选择磁盘/目录，最多 60 秒，可取消；没有找到时手动输入。
4. 程序默认放在当前用户的 `%LOCALAPPDATA%\Programs\DeadlockTranslate`，也可选其他空目录。不要选游戏目录、磁盘根目录、个人状态目录、临时目录或符号链接目录。
5. 检查 Steam 目录和账号。自动配置会先备份，只编辑所选账号的 Deadlock 启动项，保留普通游戏参数。默认允许正常退出并重启 Steam；不会强制结束游戏/Steam。退出失败时会说明启动项尚未完成。没有账号记录时，可取消自动配置并手动粘贴。
6. 检查资源冲突。已识别的 QOL 包自动忽略，不需要确认共存或停用。其他包的精确资源重叠或无法读取的 VPK 不会自动覆盖；只有明确勾选并确认，才把指定整包重命名停用。相关聊天/HUD Mod 可明确选择保留共存，实际兼容性需游戏验证。不要为继续安装盲目停用大型整合包。
7. 执行后阅读完成页，包括未完成项。首次信任证书后完整退出并重启 Steam，再从 Steam 启动游戏；打开翻译设置配置自己的服务与 API Key。

## 覆盖更新

退出 Deadlock，直接运行新版 Setup EXE，选择“安装 / 覆盖更新”。已有记录会显示版本并沿用原程序位置。无需先卸载，不要人为把旧目录改为新版本号。

安装器在更新前验证内置包的所有文件哈希，成套替换后台、网页、词库和游戏 VPK；保留个人设置、API 密钥、有效证书、普通 Steam 参数及其他 Mod。词库沿用现有更新器的合并规则。降级包被拒绝。同版本也可用于检查和重新安装原文件。

程序或 VPK 更新失败会尝试按备份回退；Steam 启动项属于后续独立步骤，配置失败时核心更新可已完成，完成页会明确说明，需要手动配置或重试。不要把“核心操作已完成”理解为全部步骤通过。

源码中的恢复补完会在检测到缺失或混包时默认选择成套修复，自定义词库保留原样。只有记录中的原目录已经丢失，才接受新的空目录作为恢复位置。安装记录丢失/损坏时使用“恢复记录”，只有所选程序 VPK 与游戏中的单个资源包哈希一致才恢复，原损坏记录先备份；不猜测原 gameinfo。无法确认归属时列出具体问题和处理路径，不强行覆盖。此前同版本包不含此补完，请使用本次完整包。

本版本为离线更新安装器，不会常驻检查新版本。以后更新仍需下载新版 Setup EXE。原 ZIP 与外置“覆盖更新.cmd”方案仍保留。

## Steam 启动项

优先由安装器按实际位置生成。手动方式：Steam → 库 → 右键 Deadlock → 属性 → 通用 → 启动选项。示例必须替换为自己的完整路径：

```text
"D:\Apps\DeadlockTranslate\DeadlockTranslate.exe" --steam-game %command%
```

已有 `-novid` 等普通参数保留在末尾。已有别的 `%command%` 启动器时不要嵌套，安装器会拒绝盲目改写，需人工协调。

游戏确实需要管理员权限时，在安装器勾选管理员兼容，生成：

```text
"D:\Apps\DeadlockTranslate\DeadlockTranslate.exe" --admin-compatible --steam-game %command%
```

安装器“更多选项 → 以管理员权限重开”仅用于受保护目录的写入权限；它与上述游戏启动权限选项是两件事。UAC 必须由原 Windows 用户确认，不支持切换另一位管理员账号。重开后重新核对当前选择。普通安装不主动提权，也不增加后台监视器、开机自启或 Windows 服务。

## 修复、卸载与异常

- 恢复补完中，“修复已有安装”对有记录的安装成套修复后台、页面、VPK、配对文件和搜索路径；已有有效证书直接沿用。没有记录时检查残留目录，提供原地重装或新空目录安装。此前同版本包尚无此补完。
- “卸载游戏组件”会停止可验证的本程序后台、移除自己的 VPK，并按安装记录处理 gameinfo。可自动检查所选 Steam 目录的所有已保存账号，只去掉指向所选翻译程序的启动前缀，不改其他账号的游戏参数或别的包装器。
- 默认保留程序目录、个人设置和备份。可选“备份并移除清单匹配的程序文件”，删除前逐文件备份并核对哈希；修改过的文件、未列入清单的文件和个人数据仍保留，因此目录可能还在。
- 可选恢复本安装器以前停用且未改变的冲突包。原位置已被占用、备份已变化或不属于当前游戏时保留备份，不强制覆盖。
- 可单独或随卸载撤销本程序证书信任，Windows 可能仍需本人确认；不会清理其他证书。卸载不会删除聊天服务的个人设置和密钥。
- 目录权限不足时可选同用户管理员重开；不要关闭系统安全功能。磁盘空间不足、文件占用、修改过的 VPK、危险路径或损坏包会停止相应步骤并提示原因。
- 缺少游戏基础文件时扫描无法修复，需要 Steam 校验文件。GUI 不能保证修复显卡驱动崩溃或所有第三方 Mod 冲突。

## 日志、备份和验证范围

### 0.6.17 的安装前检查

检查页会列出程序文件、游戏 VPK、`gameinfo.gi`、安装记录和所选 Steam 账号的检查结果。检查页不写入游戏配置；开始执行前再次检查，并用自动删除的临时文件验证目标目录的写入权限。自动配置启动项时先验证所选账号的 VDF 结构和现有包装器；缺少 Deadlock 记录时提示切换正确账号或手动配置，不创建猜测的 Apps 区块。

`gameinfo.gi` 为只读时，默认不安装。可明确勾选“临时解除只读”，仅处理这一个文件，提交后恢复属性；不更改 ACL、不解除整目录保护。旧后台占用程序文件时，更新器先正常停止已验证身份的后台，再检查这些文件。占用、权限或空间问题未解决时停止写入。

首次安装与更新使用同目录临时文件和原子替换，提交前核对原文件哈希。正常错误会按已经提交的步骤回退；回退遇到外部修改时保留修改与备份，不强制覆盖。卸载先恢复配置，再移走本 Mod 的 VPK，失败时恢复已完成的步骤。突然断电或进程被强制结束不能保证自动回退，请保留备份、导出日志后处理。

管理员重开会保存已选目录、操作模式、Steam 账号和普通选项，限定同一 Windows 用户、同一版本及 15 分钟内使用；重开后仍需要重新检查和确认。停用冲突包、共存、只读处理等确认不会自动沿用，不会自动执行安装。

常见错误：`read-only` 检查该文件属性或确认临时解除；`file-locked` 正常退出游戏/旧后台并等待扫描；`access-denied` 检查精确路径，必要时同用户管理员重开；`disk-full` 释放目标磁盘空间；`file-changed` 返回重新检测；`steam-no-game-record` 核对账号，不自行新增配置树。

安装日志：`%LOCALAPPDATA%\DeadlockTranslate-Installer\installer.log`，单文件约 1 MiB，另保留上一份。窗口内最多 400 条。点击“更多选项 → 导出安装日志”保存当前运行的 ZIP；日志可能含本地路径，不记录聊天、API Key 或整份 Steam 配置。

另有 `installer-events.jsonl`，记录会话标识、版本、系统/权限、步骤耗时，以及可定位文件的错误码、属性、HRESULT 和回退说明，同样约 1 MiB 并轮转。导出 ZIP 包含本次文字日志、结构化事件、环境和预检摘要；不收集聊天正文、请求配置、Steam 启动参数或证书私钥。诊断中空白路径表示该步骤没有提供文件诊断；分享前可检查路径中的用户名。

备份：`%LOCALAPPDATA%\DeadlockTranslate\backups`，完成页可打开。Steam 配置脚本也保留它自己的配置备份；这些备份含账号配置，不要作为公开日志上传。首次安装复制失败可能留下带 `.dlt-stage-` 或 `.dlt-failed-` 后缀的目录，日志会指明，确认无需恢复后再清理。

安装器编译、包校验、WinForms 预览以及隔离文件上的安装/更新/回退/卸载已测试。模拟测试不会自动确认 Windows 信任或 UAC，也没有替用户进行 Steam 登录和游戏内验收。发布验证见 `TEST-REPORT.md` / `docs/VALIDATION.md`。


0.6.9 修复隐藏 AppData 等父目录被误判为不存在的问题。检查期间只锁定可操作控件，正文保持可读；禁用按钮使用明确的灰底和文字。界面采用侧边步骤与浅色分组卡片，小窗口可滚动。


## 0.6.18 安装恢复补完

本次完整 0.6.18 安装器包含以下功能；此前同版本包不包含，请核对随包哈希与 featureRevision。缺失的游戏翻译 VPK 不再要求手动寻找旧包；检查页显示恢复目标，确认后从新完整包恢复，并同步后台/页面/词库/VPK。原 VPK 改名时通过唯一哈希关联；原位置被占用时不覆盖原文件，改用空 pak 槽位；重复包、无法读取的资源包或合并包冲突会列出并阻止未经确认的恢复。

后台/VPK/配对混包会列出核心文件清单校验问题，可确认成套修复；同版本也按实际文件哈希检查。保留个人状态、密钥和证书，不反复导入证书。源码中的 -RepairGameVpk 用于明确恢复，-RepairMissingRuntime 用于程序成套修复；不要仅跳过哈希检查或随意改安装记录。VPK/配对格式未知时不宣称已证明匹配。

导出日志新增文件操作阶段、原始时间、精确路径、预期与实际哈希，以及游戏 VPK 恢复方案和运行包完整性摘要。只输出配对格式/匹配布尔值，不输出凭据。Mod 管理器仍可能在下一次应用配置时重部署 addons，请确保它不同时管理第二份翻译资源；不承诺能自动协调所有管理器。


恢复补完的默认操作是“安全恢复后继续安装”：预检会自动勾选已确认的成套修复，不用另外寻找旧 VPK、改安装记录或复制配对文件。命令行更新器也会对已记录原目录默认恢复缺失/混包文件。若发现完全相同且仅含九个翻译资源的多个活动副本，保留一个活动槽位，其余移动到备份后更新，失败会恢复它们。无法确认归属或整合包包含其他功能时，可在检查页打开目录、明确勾选停用具体冲突包后继续；也可在对应管理器只关闭翻译功能再重新检查。不会静默删除其他 Mod。

有可确认安装记录时，“修复已有安装”也会成套恢复程序与游戏包；恢复方案会优先显示在检查页。没有记录时检查残留目录并成套重装，不要求先恢复旧 VPK。已有有效证书沿用，不重复导入。


## 手动删掉 Mod 后重新安装

使用本次补完后的完整 0.6.18 安装器，选择“安装 / 覆盖更新”（也支持“修复已有安装”），按证书、目录、检查页顺序继续。已有有效受信任证书沿用，不需要反复安装；已经删除的证书或私钥则需要重新准备。

如果安装记录已丢失，检查页显示重装方案：可根据清单哈希和独立翻译 VPK 资源确认的原程序目录，备份后原地成套重装；不能确认归属的非空目录保留，自动选择新的空程序目录。确认后恢复后台、设置页、配对、词库和游戏 VPK，重建安装记录。Steam 自动配置使用最终程序路径；若跳过或失败，必须粘贴完成页的新启动项，不能继续使用已删除的旧路径。

不用先卸载、手改 JSON 或找回旧 VPK；“恢复记录”找不到旧包、无记录时选择卸载，都将引导回重新安装。整个 addons 文件夹缺失也能恢复。其他 Mod 或整合包有冲突时，仍需在检查页审核具体文件；不自动删除不明文件。个人状态目录中仍存在的设置、密钥、证书及用户词库保留；已经手动删掉的个人数据只能从用户自己的备份恢复。

损坏记录会另存备份。失败时只撤销本次未完成步骤；无法证明历史 gameinfo 修改或旧冲突包归属时，不编造恢复信息。导出安装日志包含 record-inspection、reinstall-plan 和记录回退阶段，可区分“记录缺失”“记录损坏”“已确认残留”“新目录安装”。


## QOL 自动忽略（0.6.18 补完）

按本项目的兼容策略，识别为 QOL LOCK 的资源包直接跳过冲突判定：不进入冲突列表，不要求勾选共存，不要求停用，也不会修改 QOL 文件。GUI 预检和执行、脚本安装、覆盖更新及缺失 VPK 恢复使用同一规则。即使该包带原生聊天布局、气泡样式或内置聊天翻译资源，也不据此阻止安装。

通过 QOL 自身的 qollock_global/qollock_defines 样式或 qollock_translations 脚本资源识别，支持 Mod 管理器改为 pak01_dir.vpk 等数字文件名；不是直接把 pak01 槽位全部放行，也不靠文件名里随便出现 qol 就跳过其他包。其他资源包的冲突、不可读检查及目标槽位保护仍生效；QOL 占用某个槽位时保留它，翻译包选择可用槽位。安装操作日志保留 conflict-scan / qol-ignored 元数据，方便确认规则已生效。
